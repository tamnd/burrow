# The files that still reach for an operating system outside src/pal/.
#
# Every line here is work that has not been done yet, not a decision. The rule
# is that everything above src/pal/ is portable C, and each of these predates
# the platform layer by a few milestones. tools/check-pal.sh fails if a file
# reaches and is not listed, and fails again if a file is listed and has stopped
# reaching, so the only edit this file ever takes is a deletion.
#
# Three columns, tab separated.
#
#   <file>  <what it wants>  <which PAL group takes it, and when>
#
# Nothing goes on this list without a group and a milestone in the third column.
# A file with nowhere to go is a file that is never coming off.

src/runtime/mcontext.c	ucontext on POSIX and the fiber API on Windows, to switch a goroutine's stack.	None, and this one is deliberate. A context switch is assembly and a kernel interface in equal measure, it is on the hottest path in the runtime, and putting a call boundary in the middle of it would cost more than the tidiness is worth. docs/design/10-packages-os.md section 2 lists no entry point for it. This line stays.
src/runtime/trace.c	The Windows stack walker, for a backtrace on a platform with no unwinder we can reach.	None yet, and no group covers it. Symbolisation turned out not to need one, since the table is a generated C file and the lookup is arithmetic, so what is left here is the walk itself. A group for that would be one entry point with a real implementation on Windows and nothing on POSIX, where the walk is ours and portable, and a PAL group with one platform in it is a worse boundary than this line. It comes off when there is a second platform that cannot walk its own frames.
