# The files that still reach for an operating system outside src/pal/.
#
# Every line here is work that has not been done yet, not a decision. The rule
# is that everything above src/pal/ is portable C, and each of these predates
# the platform layer by a few milestones. tools/check-pal.sh fails if a file
# reaches and is not listed, and fails again if a file is listed and has stopped
# reaching, so the only edit this file ever takes is a deletion.
#
# Three columns, tab separated.
#
#   <file>  <what it wants>  <which PAL group takes it, and when>
#
# Nothing goes on this list without a group and a milestone in the third column.
# A file with nowhere to go is a file that is never coming off.

include/burrow/note.h	A pthread mutex and condition variable inline in the struct, so that a Note can be a value and not an allocation.	Threads, once pal_futex_wait and pal_futex_wake land. The struct becomes a word and a wait queue and the header stops needing pthread at all.
include/burrow/thread.h	pthread_t inline in the handle, for the same reason.	Threads, alongside note.h. The handle becomes the int64_t that pal_thread_create returns.
src/runtime/mcontext.c	ucontext on POSIX and the fiber API on Windows, to switch a goroutine's stack.	None, and this one is deliberate. A context switch is assembly and a kernel interface in equal measure, it is on the hottest path in the runtime, and putting a call boundary in the middle of it would cost more than the tidiness is worth. docs/design/10-packages-os.md section 2 lists no entry point for it. This line stays.
src/runtime/netpoll_epoll.c	epoll, eventfd, close.	Poll. The four entry points are declared in burrow/pal.h and this file becomes src/pal/poll_linux.c mostly unchanged.
src/runtime/netpoll_kqueue.c	kqueue, a pipe for the wakeup, fcntl for non blocking.	Poll, alongside the epoll backend. Becomes src/pal/poll_bsd.c.
src/runtime/netpoll_iocp.c	A completion port.	Poll, alongside the other two. Becomes src/pal/poll_windows.c.
src/runtime/note.c	A futex on Linux, pthread elsewhere, and WaitOnAddress on Windows.	Threads. The three of those are what pal_futex_wait is, and this file becomes portable C over it.
src/runtime/stack.c	mmap and mprotect, VirtualAlloc, and a fault handler for the guard page.	Memory for the mapping half, which is pal_vm_reserve and the four calls next to it and is already written. The handler half is Misc, waiting on pal_signal_install. The file stops being per platform once both are in.
src/runtime/thread.c	pthread_create, _beginthreadex, and the affinity calls.	Threads, alongside note.c.
src/runtime/trace.c	The Windows stack walker, for a backtrace on a platform with no unwinder we can reach.	None yet, and no group covers it. Symbolisation is its own item on the P0 list and the shape of it is not settled, so this line is honest about not having an answer rather than inventing a group to put it in.
