# Every mutable global in burrow's own source, one per line.
#
# Reentrancy is a requirement, not a preference, so global mutable state is
# enumerated rather than merely discouraged. This file is the enumeration, and
# tools/check-globals.sh fails the build when the tree and this file disagree in
# either direction: a global that is not listed here, or a line here whose global
# no longer exists. A list that can rot is a list nobody trusts.
#
# Adding a global means adding a line, which means a reviewer sees it in the
# diff and gets to ask the question. That is the entire point. The question is
# not "is this convenient", it is "what happens when two threads reach it", and
# the answer goes in the last column.
#
# Two kinds of line, tab separated.
#
#   category  <name>  <what it covers>
#   global    <file>  <symbol>  <category>  <how it is synchronised>
#
# The categories come from docs/design/03-c-dialect.md section 5. Some of them
# have no members yet because the code they belong to is not written, and they
# are here so that the work has somewhere to go rather than somewhere to be
# invented.

category	scheduler	Ps, Ms, run queues, everything that is the runtime itself.
category	netpoller	The epoll, kqueue or IOCP handle. One per process is correct.
category	type-registry	Process wide type identity, which is what reflect needs.
category	allocator	Allocator singletons and their per process state.
category	time-zone-cache	LoadLocation's cache, which matches what Go does.
category	signal-table	Signal disposition, because the OS has one per process.
category	package-vars	os.Args, os.Stdout and the rest that Go exposes as package level variables.
category	marker	An address that exists to be unique. Never read through, never written.
category	fatal-handler	Where an unrecoverable runtime failure goes before the process ends.
category	rand	The generator behind map iteration order and hash seeding.
category	atomic-lock-table	The spin locks that stand in for 64 bit atomics on machines that do not have them.
category	sema-table	The wait queues behind sync, keyed on the address of the counter being waited on, which is what makes them one per process by definition.
category	futex	The wait queues that stand in for a futex on the platforms that have no such call, keyed on the address being waited on, which is what makes them one per process by definition.
category	reclaim	The epoch and the handover lists behind lock free reading. One epoch per process is the whole idea, since a reader on any thread has to be able to hold any of them back.
category	pool	sync.Pool's registry and the lock over it, which is one per process because the sweep has to be able to find every pool from the system monitor's thread.
category	clock	The conversion factor between what the machine's counter counts and nanoseconds. Fixed at boot, so it is asked for once.
category	machine	What the machine is: the page size and how many cores the process may run on. Both are fixed for the life of the process, so both are asked for once.

global	src/core/slice.c	zerobase	marker	Never written. Every zero sized allocation returns this address, and a copy into it is a copy of zero bytes.
global	src/mem/track.c	tomb	marker	Never written. It is the deleted slot marker, and it is a real object because casting a small integer to a pointer is not defined and this is.
global	src/mem/heap.c	heap_singleton	allocator	Immutable except through mem_set_oom, which is documented as a decision the host makes once, before there is a second thread.
global	src/mem/gc.c	gc_singleton	allocator	The same as heap_singleton. One collector in a process means one object.
global	src/mem/gc.c	started	allocator	Written once by the first gc_allocator call, which the header requires to come from the main thread before any others exist.
global	src/runtime/mcontext.c	resuming	scheduler	Thread local, and it only exists on the ucontext path. Written by a switch and read by the trampoline on the other side of that same switch, on the same thread, with nothing in between.
global	src/runtime/mcontext.c	annotate_prev	scheduler	Thread local, and it only exists in a build with the address sanitizer on. Written on the old stack and read on the new one, on the same thread, with nothing in between, the same as resuming above.
global	src/runtime/mcontext.c	tsan_pool_lock	scheduler	This is the synchronisation for the three below, and it only exists in a build with the thread sanitizer on. Held for the handful of instructions that move a fiber into or out of the pool, never across the call that makes one.
global	src/runtime/mcontext.c	tsan_pool	scheduler	The spare fibers, under tsan_pool_lock above. Shared rather than thread local because the goroutine that frees a context is often not the one that made it, so a per thread pool would drift until one thread had all the fibers and another had none.
global	src/runtime/mcontext.c	tsan_pool_len	scheduler	How many of the pool are spare, under tsan_pool_lock above.
global	src/runtime/mcontext.c	tsan_fibers_made	scheduler	How many fibers this process has ever asked the sanitizer for, under tsan_pool_lock above. It only goes up, because the sanitizer never gives an identifier back, and that is the whole reason there is a budget to count against.
global	src/runtime/stack.c	armed	signal-table	Three states and a compare and swap between them. The thread that wins installs the handlers and publishes the done state with a release, and the threads that lose spin on an acquire load rather than answering yes while the handler is still not there.
global	src/runtime/stack.c	current	scheduler	Thread local. Written by whoever switched to this stack and read by the fault handler on the same thread, which is the one place a signal handler is allowed to look at.
global	src/runtime/stack.c	prev_bus	signal-table	Written once by the thread that wins the arm, before that thread publishes the done state, and read only from a handler that cannot run until after it. The signal disposition is per process because the operating system says so.
global	src/runtime/stack.c	prev_segv	signal-table	The same as prev_bus, for the other signal.
global	src/runtime/stack.c	signal_stack	scheduler	Thread local, and only ever touched by the thread it belongs to. It is the mapping sigaltstack was given, kept so that disarming can give it back.
global	src/runtime/stack.c	veh	signal-table	Windows only. The handle from AddVectoredExceptionHandler, kept so that a second arm can tell it has already happened.
global	src/runtime/panic.c	fatal_handler	fatal-handler	Written once during startup and read on the way out. Becomes an atomic load when sync/atomic lands, which weakens the contract rather than changing any caller.
global	src/runtime/rand.c	rand_state	rand	Thread local, which is what makes it lock free. A shared generator would be a place for two goroutines to contend over bits neither of them cares about.
global	src/runtime/atomic64.c	locks	atomic-lock-table	This is the synchronisation. A table of spin locks, one taken for the duration of each 64 bit operation, chosen by hashing the address so that unrelated counters rarely meet.
global	src/runtime/sema.c	semtable	sema-table	251 roots, each with its own lock and each holding the waiters for every address that hashed to it. A waiter is on exactly one root and every read and write of a root happens under that root's lock, except the waiter count, which is atomic so that an uncontended release can skip the lock entirely.
global	src/runtime/sched.c	sched	scheduler	The scheduler itself, which is one per process because a second one would be a second set of threads fighting the first over the same cores. Every field is either under sched.lock or an atomic, and the comment on each one says which.
global	src/runtime/sched.c	allp	scheduler	The Ps, a fixed array rather than an allocation so that the scheduler has nothing underneath it that can fail. A P is owned by at most one M at a time and that ownership is what makes its ring safe to touch.
global	src/runtime/sched.c	allm	scheduler	The Ms, the same fixed array for the same reason. An entry is handed out once by newm under sched.lock and belongs to that thread until the run is over.
global	src/pal/time_windows.c	qpc_ready	clock	Windows only. Written with a release once the two halves below hold the tick rate, and read with an acquire, so a thread that sees it set also sees them. Two threads racing here ask the kernel twice and write the same number twice, which costs a duplicate call and nothing else.
global	src/pal/time_windows.c	qpc_lo	clock	Windows only. The low 32 bits of the tick rate, in two halves because a 64 bit atomic on a 32 bit machine takes a lock and this is read on every clock reading.
global	src/pal/time_windows.c	qpc_hi	clock	Windows only. The high 32 bits, published by the same release store as the low ones.
global	src/pal/time_darwin.c	timebase_numer	clock	macOS only. The numerator of the tick to nanosecond fraction, written before the denominator below and read after it.
global	src/pal/time_darwin.c	timebase_denom	clock	macOS only. The denominator, and the flag. Written with a release and nonzero means both it and the numerator are readable, the same arrangement as qpc_ready above with one fewer variable because a denominator of zero is already impossible.
global	src/runtime/sched.c	curm	scheduler	Thread local. It is which M this thread is, written when the thread starts and cleared when it stops, and read by everything that needs to know which P it may use.
global	src/runtime/defer.c	thread_scopes	scheduler	Thread local, and only reachable from a thread that is not running a goroutine. A goroutine's defer chain is a field of the goroutine, because a goroutine that parks inside a scope can wake up on another thread.
global	src/runtime/panic.c	thread_panic	scheduler	Thread local, and only reachable from a thread that is not running a goroutine. A goroutine keeps its panics and its recovery points in the goroutine, for the reason the defer chain is there: a goroutine that parks inside a BURROW_TRY can wake up on another thread.
global	src/runtime/trace.c	thread_lo	scheduler	Thread local. The bottom of the stack this thread was given, asked for once because asking goes to the kernel on both Linux and macOS, and kept because a thread keeps its stack for as long as it exists.
global	src/runtime/trace.c	thread_hi	scheduler	Thread local. The top of the same stack, written by the same first walk that fills the one above.
global	src/runtime/trace.c	thread_asked	scheduler	Thread local. Whether the two above have been filled in, which is a separate flag because a system that will not say gets asked once rather than on every walk.
global	src/runtime/reclaim.c	slots	reclaim	This is the synchronisation. One word per participant, each on its own cache line, written only by the thread that owns it and read by whoever is trying to move the epoch on. The store that pins is sequentially consistent so that the reads it protects cannot be hoisted above it.
global	src/runtime/reclaim.c	cur_epoch	reclaim	Atomic. Read by every pin and written only under bag_lock by a thread that has just walked the slots and found nobody behind.
global	src/runtime/reclaim.c	mhigh	reclaim	Atomic, and only ever raised. How far into the goroutine half of slots anybody has been, so the walk stops there. Raised before the slot it describes is published, which is what stops a walk from missing a pin.
global	src/runtime/reclaim.c	fhigh	reclaim	The same as mhigh, for the half that foreign threads take from.
global	src/runtime/reclaim.c	bag_lock	reclaim	This is the synchronisation for the three lists below and for the write to cur_epoch. Held for a splice and a walk of the slots, never across a free.
global	src/runtime/reclaim.c	bag	reclaim	The handed over objects, one list per epoch modulo three, under bag_lock above.
global	src/runtime/reclaim.c	bag_since	reclaim	How many objects have arrived on the bags since the last walk of the slots, under bag_lock above. It is the thing that decides whether this arrival pays for a walk.
global	src/runtime/reclaim.c	pending	reclaim	Atomic counter, and nothing reads it to make a decision. It is there so a test and a debugger can see how much is waiting.
global	src/runtime/reclaim.c	pockets	reclaim	What each M has retired and not yet pushed. Only the thread running that M touches its own entry, and the only reason they are an array rather than thread local is so that burrow__reclaim_drain can find them all at the end.
global	src/runtime/reclaim.c	my_slot	reclaim	Thread local. Which slot this thread is pinned through, written and read by that thread alone.
global	src/runtime/reclaim.c	my_depth	reclaim	Thread local. How many pins deep this thread is, so a pin inside a pin publishes once.
global	src/runtime/sched.c	sweepfn	scheduler	The callback the system monitor makes on its timer, which is sync.Pool's sweep and nothing else today. Set at most once, from the first pool anybody uses, and published by the flag below rather than written atomically, because C says nothing about atomic operations on function pointers.
global	src/runtime/sched.c	sweepset	scheduler	Whether the pointer above has been set. A release store here and an acquire load in sysmon are what make the plain write to sweepfn visible to the monitor's thread.
global	src/sync/pool.c	pools_lock	pool	This is the synchronisation for the list below. Held for the length of a sweep, which is a walk of every pool's victim shard, so it is the one lock in the package that is held for a while rather than for a few instructions.
global	src/sync/pool.c	allpools	pool	Every pool that has been used, so that the sweep can find them. A pool goes on the list the first time it is touched and comes off in sync_pool_free, both under pools_lock above.
global	src/runtime/netpoll.c	cache_lock	netpoller	The lock over the descriptor table below. Taken only to make a block or move a descriptor on or off the free list, which is once per connection and never on the path an event takes.
global	src/runtime/netpoll.c	cache_first	netpoller	The free list of descriptors, under cache_lock. A descriptor is never given back to the heap, so a slot handed out here has been used before and its generation says how many times.
global	src/runtime/netpoll.c	cache_blocks	netpoller	The blocks of descriptors, published with a release store under cache_lock and read without it. A block is only ever added, never moved or freed, which is what makes the read safe.
global	src/runtime/netpoll.c	cache_ndescs	netpoller	How many descriptors exist, raised last when a block is added so that a reader that sees the count sees the block.
global	src/runtime/netpoll.c	init_lock	netpoller	The lock the poller is started under, so that two goroutines opening their first descriptor at once make one epoll or kqueue between them.
global	src/runtime/netpoll.c	init_done	netpoller	Whether the poller is started. A release store under init_lock and an acquire load everywhere else, which is what lets the scheduler ask the question without taking anything.
global	src/runtime/netpoll.c	netpoll_nwaiters	netpoller	How many goroutines are parked on a descriptor. Atomic, and read by the scheduler to decide whether a poll could find anything.
global	src/pal/poll_linux.c	epfd	netpoller	The epoll descriptor. One per process, made once by pal_poll_create and read without anything afterwards.
global	src/pal/poll_linux.c	breakfd	netpoller	The eventfd a wakeup is written to, made alongside epfd and read the same way.
global	src/pal/poll_linux.c	wakesig	netpoller	Whether a wakeup is already on its way. Atomic, set by a compare and swap so that many wakeups at once cost one write, and cleared by whoever drains the eventfd.
global	src/pal/poll_bsd.c	kq	netpoller	The kqueue descriptor. One per process, made once by pal_poll_create and read without anything afterwards.
global	src/pal/poll_bsd.c	breakrd	netpoller	The read end of the wakeup pipe, which is what the kqueue watches.
global	src/pal/poll_bsd.c	breakwr	netpoller	The write end of the wakeup pipe, which is where a byte goes to interrupt a wait.
global	src/pal/poll_bsd.c	wakesig	netpoller	Whether a wakeup is already on its way. Atomic, set by a compare and swap so that many wakeups at once cost one byte, and cleared by whoever drains the pipe.
global	src/pal/poll_windows.c	iocp	netpoller	The completion port. One per process, made once by pal_poll_create and read without anything afterwards.
global	src/pal/poll_windows.c	wakesig	netpoller	Whether a wakeup is already on its way. Atomic, set by a compare and swap so that many wakeups at once cost one posted completion, and cleared by whoever takes that completion off the port.
global	src/runtime/netpoll_readiness.c	poller	netpoller	The PAL's handle for the poller. Set once by the backend init, which runs under init_lock, and read without anything afterwards.
global	src/runtime/netpoll_completion.c	poller	netpoller	The PAL's handle for the completion port. Set once by the backend init, which runs under init_lock, and read without anything afterwards.
global	src/pal/futex_posix.c	buckets	futex	The wait queues, sixty four of them, each a mutex and a condition variable and a list. Fixed at compile time because nothing in the PAL allocates, and an address always hashes to the same one.
global	src/pal/futex_posix.c	setup_once	futex	Guards the one pass that initialises the table. A pthread_once, because a condition variable's clock cannot be set by a static initialiser.
global	src/pal/futex_posix.c	setup_ok	futex	Whether that pass worked. Written inside the once and read after it, which is what makes it safe without an atomic. A false here makes every wait and wake fail loudly rather than return as if it had slept.
global	src/pal/futex_windows.c	buckets	futex	The same sixty four wait queues over an SRWLOCK and a CONDITION_VARIABLE. Both have a static initialiser that is a zeroed structure, so this table needs no setup pass at all.
global	src/runtime/registry.c	registry_once	type-registry	Guards the one read of the linker section that builds the table. A Once, so whoever loses the race waits for the table rather than seeing half of one.
global	src/runtime/registry.c	registry_lock	type-registry	The reader writer lock over the three fields below. Read on every lookup, taken for writing only by type_register, which is the runtime half nothing uses until a module is loaded after startup.
global	src/runtime/registry.c	registry_slots	type-registry	The table. Written under registry_lock when it is built and when it grows, read under it the rest of the time.
global	src/runtime/registry.c	registry_cap	type-registry	How many slots there are, always a power of two. Same lock as the table it describes, because the two have to change together.
global	src/runtime/registry.c	registry_len	type-registry	How many of the slots are taken. Same lock, same reason.
global	src/pal/machine_posix.c	cached_page	machine	Relaxed atomic, and the race is benign by construction. Two threads arriving together both ask the system, both get the same number, and both write it. There is nothing published alongside it, so there is nothing for a release store to order.
global	src/pal/machine_windows.c	cached_page	machine	The Windows half of cached_page above, with the same reasoning.
